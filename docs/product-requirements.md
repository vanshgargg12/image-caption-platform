# Product Requirements

## Purpose

The Image Caption Platform accepts user-uploaded images and returns natural-language
captions generated by a pretrained ONNX-compatible image-captioning model served through
Transformers.js.

## MVP Goals

1. Provide a simple web UI for uploading an image and viewing a caption.
2. Route all public traffic through a Spring Boot API; the browser never calls the
   inference service directly.
3. Run inference in an internal Node.js service that loads the model once and reuses it.
4. Start with `Xenova/vit-gpt2-image-captioning`; add Florence-2 only after the basic
   end-to-end flow works.
5. Ship each phase with tests, documentation, and local verification commands.

## Non-Goals (MVP)

- Authentication and user accounts
- Batch processing
- OCR or object detection
- Redis, Kafka, or Kubernetes
- Permanent storage of uploaded images by default
- Python anywhere in runtime, scripts, tests, evaluation, or deployment

## System Boundaries

| Component  | Role                                      | Exposure   |
|------------|-------------------------------------------|------------|
| Frontend   | Next.js UI                                | Public     |
| Backend    | Spring Boot public API                    | Public     |
| Inference  | Transformers.js model service             | Internal   |

Public flow: **Frontend → Backend → Inference**

## Functional Requirements (Upcoming Phases)

- Upload image via frontend; backend validates content type from bytes, not client metadata.
- Backend forwards validated requests to inference and returns structured responses/errors.
- Inference loads a pinned model revision once at startup and serves caption requests.
- APIs return structured errors with stable machine-readable codes.

## Current Status

Phase 0 complete: monorepo scaffolding with minimal buildable frontend, backend, and
inference services. Model inference, image upload, and database integration are not
implemented yet.
